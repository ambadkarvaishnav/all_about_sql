## 1️⃣ Assumed Database Schema


```bash
 Customers (
    customer_id INT PRIMARY KEY,
    customer_name VARCHAR(100),
    signup_date DATE
);

Drivers (
    driver_id INT PRIMARY KEY,
    driver_name VARCHAR(100),
    rating DECIMAL(2,1),
    cab_type VARCHAR(20) -- Sedan, SUV
);

Bookings (
    booking_id INT PRIMARY KEY,
    customer_id INT,
    driver_id INT,
    booking_time DATETIME,
    trip_start_time DATETIME,
    trip_end_time DATETIME,
    status VARCHAR(20), -- Completed, Cancelled
    pickup_location VARCHAR(100),
    dropoff_location VARCHAR(100),
    fare DECIMAL(10,2),
    distance_km DECIMAL(6,2),
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id),
    FOREIGN KEY (driver_id) REFERENCES Drivers(driver_id)
);

Feedback (
    feedback_id INT PRIMARY KEY,
    booking_id INT,
    rating INT,
    comments VARCHAR(255),
    cancellation_reason VARCHAR(100),
    FOREIGN KEY (booking_id) REFERENCES Bookings(booking_id)
);
```

## 📊 CUSTOMER & BOOKING ANALYSIS

1. Customers who cancelled > 30% of their bookings


```bash
SELECT 
    customer_id,
    COUNT(*) AS total_bookings,
    SUM(CASE WHEN status = 'Cancelled' THEN 1 ELSE 0 END) AS cancelled_bookings,
    (SUM(CASE WHEN status = 'Cancelled' THEN 1 ELSE 0 END) * 100.0 / COUNT(*)) AS cancel_pct
FROM Bookings
GROUP BY customer_id
HAVING cancel_pct > 30;

```
### 🧩 CONCEPT MAPPING

```bash
Raw Rows
   ↓
GROUP BY customer_id
   ↓
COUNT + CASE WHEN
   ↓
Percentage Calculation
   ↓
HAVING filter (>30%)

```

Insight:

Frequent cancellations may indicate:

Long waiting time

Driver unavailability

Price sensitivity

👉 Improve ETA accuracy & cancellation penalties.

✔ GROUP BY   
✔ CASE WHEN  
✔ Aggregate functions  
✔ HAVING vs WHERE  
✔ Percentage calculation       



2. Busiest day of the week

```bash
SELECT 
    DAYNAME(booking_time) AS day,
    COUNT(*) AS total_bookings
FROM Bookings
GROUP BY day
ORDER BY total_bookings DESC
LIMIT 1;

```

### 🧩 CONCEPT MAPPING

```bash
Datetime column
      ↓
DAYNAME()  →  Extract weekday
      ↓
GROUP BY day  →  Combine same weekdays
      ↓
COUNT(*)  →  Total bookings per day
      ↓
ORDER BY DESC  →  Highest first
      ↓
LIMIT 1  →  Pick top day


```


Optimization:

Increase driver supply

Dynamic surge pricing

Pre-allocate cabs in advance

🧠 Key Concepts Used

✔ Date/Time function (DAYNAME)  
✔ Aggregation (COUNT)

✔ Sorting (ORDER BY)  
✔ Top-N logic (LIMIT)

## 💰 REVENUE ANALYSIS

1. Revenue in last 6 months + trend

```bash
SELECT 
    DATE_FORMAT(trip_end_time, '%Y-%m') AS month,
    SUM(fare) AS revenue
FROM Bookings
WHERE status = 'Completed'
  AND trip_end_time >= DATE_SUB(CURDATE(), INTERVAL 6 MONTH)
GROUP BY month
ORDER BY month;

```
### 🧩 CONCEPT MAPPING

```bash
All bookings
     ↓
WHERE status = 'Completed'
     ↓
WHERE last 6 months (DATE_SUB + CURDATE)
     ↓
DATE_FORMAT → extract Year-Month
     ↓
GROUP BY month
     ↓
SUM(fare) → revenue
     ↓
ORDER BY month (time series)

```

🧠 Key Concepts You’re Practicing

✔ Date Formatting(DATE_FORMAT(date, '%Y-%m')   
✔Time-Based Filtering(DATE_SUB(CURDATE(), INTERVAL 6 MONTH))   
✔ Grouping (GROUP BY)  
✔ Sorting (ORDER BY)  
✔ WHERE vs GROUP BY
WHERE filters rows
GROUP BY summarizes data

3. Correlation: Driver rating vs earnings

```bash
SELECT 
    d.driver_id,
    d.rating,
    COUNT(b.booking_id) AS completed_trips,
    SUM(b.fare) AS total_earnings
FROM Drivers d
JOIN Bookings b ON d.driver_id = b.driver_id
WHERE b.status = 'Completed'
GROUP BY d.driver_id, d.rating
ORDER BY d.rating DESC;

```
### 🧩 CONCEPT MAPPING

```bash
Drivers table
      ↓
JOIN Bookings on driver_id
      ↓
WHERE status = 'Completed'
      ↓
GROUP BY driver_id, rating
      ↓
COUNT(booking_id) → completed_trips
      ↓
SUM(fare) → total_earnings
      ↓
ORDER BY rating DESC

```
🧠 KEY CONCEPTS USED  
✔ 1. INNER JOIN

Combines rows where driver_id exists in both tables

✔ 2. Table Aliases

d, b make query cleaner and readable

✔ 3. Aggregate Functions

COUNT() → number of trips

SUM() → total earnings

✔ 4. GROUP BY with Non-Aggregated Columns

All selected non-aggregated columns must be grouped

✔ 5. Row-Level Filtering

WHERE filters bookings before aggregation

✔ 6. Ranking with ORDER BY

Sorts drivers based on business priority (rating)

### 🔮 PREDICTIVE & STRATEGIC ANALYSIS

1. Customers likely to churn

```bash
SELECT 
    customer_id,
    MAX(booking_time) AS last_booking,
    COUNT(*) AS total_rides
FROM Bookings
GROUP BY customer_id
HAVING last_booking < DATE_SUB(CURDATE(), INTERVAL 3 MONTH)
   AND total_rides < 5;

```
### 🧩 CONCEPT MAPPING

```bash
Bookings table
      ↓
GROUP BY customer_id
      ↓
MAX(booking_time) → last booking date
      ↓
COUNT(*) → total rides
      ↓
HAVING last_booking < today - 3 months
      ↓
AND total_rides < 5

```

🧠 KEY CONCEPTS USED  

✔ 1. Aggregate Functions

MAX() → most recent activity

COUNT() → engagement level

✔ 2. Customer Recency & Frequency (RFM Concept)

Recency → last_booking

Frequency → total_rides

Common in CRM & marketing analytics

✔ 3. HAVING Clause

Filters aggregated results

Required when conditions use MAX, COUNT

✔ 4. Dynamic Date Filtering
DATE_SUB(CURDATE(), INTERVAL 3 MONTH)


Automatically adjusts with current date

✔ 5. Churn / Risk Segmentation

Identifies customers for:

Re-engagement campaigns

Discounts & offers

Retention analysis

3. Drivers with avg rating < 3 in last 3 months

```bash
SELECT 
    d.driver_id,
    AVG(f.rating) AS avg_rating
FROM Drivers d
JOIN Bookings b ON d.driver_id = b.driver_id
JOIN Feedback f ON b.booking_id = f.booking_id
WHERE b.trip_end_time >= DATE_SUB(CURDATE(), INTERVAL 3 MONTH)
GROUP BY d.driver_id
HAVING avg_rating < 3.0;

```

### 🧩 CONCEPT MAPPING
```bash
Drivers table
      ↓
JOIN Bookings → link driver trips
      ↓
JOIN Feedback → link feedback to trips
      ↓
WHERE last 3 months
      ↓
GROUP BY driver_id
      ↓
AVG(rating) → avg_rating per driver
      ↓
HAVING avg_rating < 3.0 → low-rated drivers

```

🧠 KEY CONCEPTS USED  

✔ 1. Multi-Table JOINs

Connects driver → booking → feedback

✔ 2. Aggregate Function – AVG

Computes average rating per driver

✔ 3. HAVING Clause

Filters aggregated values, not raw rows

✔ 4. Time-Based Filtering

Only considers recent trips for relevance

✔ 5. Quality / Performance Metric

Helps identify:

Poor-performing drivers

Training or intervention needs

Customer satisfaction issues
